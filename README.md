# DevBoard

A full-stack project management app — NestJS 11 API + React 19 frontend in a pnpm monorepo.

## Quick start

```bash
# 1. Copy and fill in environment files
cp devboard-back/.env.example devboard-back/.env
cp devboard-front/.env.example devboard-front/.env   # set VITE_API_BASE_URL=http://localhost:3000

# 2. Install dependencies
pnpm install

# 3. Start the database
pnpm db:up

# 4. Run migrations and seed data
pnpm db:migrate
pnpm db:seed

# 5. Generate the API client from the OpenAPI spec
pnpm generate:api

# 6. Start both frontend and backend in parallel
pnpm dev
```

## Monorepo scripts

| Script                  | Description                                                        |
|-------------------------|--------------------------------------------------------------------|
| `pnpm dev`              | Start frontend + backend in parallel (watch mode)                  |
| `pnpm build`            | Build backend first, then frontend                                 |
| `pnpm test`             | Run all tests (frontend + backend)                                 |
| `pnpm lint`             | Lint all packages                                                  |
| `pnpm generate:api`     | Export OpenAPI spec from backend, then generate Orval client       |
| `pnpm db:up`            | Start PostgreSQL in Docker                                         |
| `pnpm db:migrate`       | Run Prisma migrations (dev)                                        |
| `pnpm db:seed`          | Seed the database with sample data                                 |

## API client architecture

The frontend owns its own types. Components and TanStack Query hooks never import Orval-generated types — they only use the Zod schemas defined in `features/*/schemas/`.

```
Component / TanStack Query hooks
    ↓  (Project, Task — Zod front types)
services/project.service.ts   ← adapter layer: calls Orval + Zod.parse()
    ↓
services/generated/projects.ts  ← generated by Orval (backend types)
    ↓
Backend REST API
```

### Regenerating the API client

After any backend change that affects the API shape:

```bash
pnpm generate:api
```

This runs two steps automatically:
1. `devboard-back`: exports a fresh `openapi.yaml` from the running NestJS app
2. `devboard-front`: regenerates `src/api/services/generated/` and `src/api/model/` from the spec
